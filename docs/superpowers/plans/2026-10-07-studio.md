# ClaudeModz Studio Implementation Plan

**Goal:** Ship a working visual editor that exports tested Claude Code mods.
**Architecture:** Shared schema and pure runtime feed both a React preview and generated plugin files. All editor data stays in the browser; a static build needs no backend.
**Tech stack:** TypeScript, Zod, React, Vite, fflate, Vitest, Claude native testing.
**Spec:** `docs/superpowers/specs/2026-10-07-studio-design.md`.

## Global constraints

Claude Code 2.1.288+; AbovePrompt only; three templates; no arbitrary execution or external services; sample values only in preview; preserve existing registry checks; no attribution trailers.

## Review focus

- Invalid and oversized imports, URL fragments, and persisted data must not overwrite a valid project.
- Configured text containing quotes, Unicode, markup, and code-like strings remains data in browser and exported plugin.
- Unknown context is not displayed as zero; stale turn completion must not replace a newer turn.
- Widget identity and checklist state survive reordering without crossing between widgets.
- Downloaded ZIP files and shared configurations must reproduce the actual editor state.
